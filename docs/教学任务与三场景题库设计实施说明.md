# 三场景实训任务与方案计算说明

## 1 用途

本文件规定教师如何配置场景任务、学生如何提交飞行方案，以及系统如何使用 GIS 数据和仿真运行结果判定方案是否满足任务条件。这里的“题库”指场景任务模板和验收条件，不是选择题或文字问答集合。

每个任务由以下内容组成：

- **任务目标**：需要完成的配送、巡检、编队程序或应急处置；
- **空间条件**：任务区域、起降点、配送点、巡检对象、建筑、地形、限制区和地面敏感区；
- **飞行器参数**：机型、最大速度、爬升/下降率、运行高度、载荷、续航、能量容量和安全余量；
- **运行条件**：风场、通信、定位、任务时间窗、事件注入时刻和可用地面保障设施；
- **验收条件**：必须满足的硬约束、指标阈值和允许的处置动作。

教师发布任务时冻结上述版本。学生可以形成多套方案并运行比较；只要方案满足全部硬约束，且指标达到任务阈值，即可判定为合格。系统不生成唯一答案，也不使用预设航线替代学生方案。

## 2 角色与流程

| 角色 | 工作内容 | 产物 |
|---|---|---|
| 教师 | 选择场景模板，配置区域、机型、规模、事件、时间窗、能源设施和指标阈值；发布任务；查看方案运行结果并给出课程评价 | 已发布任务版本、指标阈值、班级项目 |
| 学生 | 读取任务条件，在二维 GIS 中编辑区域、航线、任务分配和时刻表；提交方案；启动仿真并按事件处置；比较不同方案 | 方案版本、仿真运行记录、指标结果、方案说明 |
| 管理员 | 维护地图、建筑、地形、机型、事件和充换电设施资源 | 可供任务引用的资源版本 |

学生流程为：`读取条件 → 形成方案 → 空间/性能预检 → 提交方案 → 运行仿真 → 处置事件 → 查看指标 → 修改或提交`。未通过预检的方案不得进入正式运行；运行结束后可以复制为新方案继续比较。

## 3 任务模板与方案数据

### 3.1 教师配置项

教师配置的不是题干和标准答案，而是可计算的场景参数：

1. **目标**：配送订单完成、巡检对象覆盖、编队程序完成或指定事件处置；
2. **资源**：WGS84 区域、建筑和障碍物、地形高程、限制区、起降点、配送点、巡检点、通信覆盖、充电站和换电站；
3. **机队**：机型及每架初始电量、健康度、载荷、速度范围、最大爬升率、最大运行高度、最大航程和返航余量；
4. **约束**：空间边界、建筑净空、地面风险区、飞行高度、机间隔离、时间窗、载荷、能量余量、充换电时间和保障点容量；
5. **事件**：天气、通信、定位、设备、航线、订单或地面设施变化，以及事件触发时间和可用处置动作；
6. **指标**：名称、单位、计算方式、合格阈值和是否为硬约束。

任务模板只允许绑定已有的指标编码。指标没有服务端计算来源时，不能配置为自动判定条件。

### 3.2 学生方案

一个方案至少包含：

- 航线航点、航段高度、速度、起降点和备降点；
- 航空器与任务的分配、起飞顺序和时刻表；
- 订单或巡检对象的访问顺序；
- 充电、换电、等待、返航和应急降落安排；
- 事件处置动作及动作触发条件；
- 方案版本号和修改说明。

学生可以提交 `方案 A`、`方案 B` 等多个版本。版本之间只比较实际输入和计算结果，不比较文字长短。提交后，方案输入锁定；复制方案后产生新的可编辑版本。

## 4 计算与判定规则

### 4.1 计算原则

仿真服务端使用任务发布版本、学生方案版本、地图资源版本和机型参数计算。浏览器提交的指标数值一律忽略，学生不能手工填写“无碰撞”“已完成”或“剩余电量”。每次运行保存仿真时钟、航空器状态、航点位置、事件、动作和资源消耗，指标从这些运行数据重新计算。

判定分两层：

- **硬约束**：任意一项不满足，方案状态为“不具备执行条件”；
- **任务指标**：硬约束通过后，按教师设置的阈值判定“达到要求”或“未达到要求”。

多个方案都可以合格。教师可按完成时间、能量消耗、风险次数、设备利用率等指标比较方案，但系统不把某一套方案称为唯一最优答案。

### 4.2 必须计算的指标

| 指标编码 | 定义 | 判定方式 |
|---|---|---|
| `FLIGHT_TIME` | 每架航空器从实际起飞到降落的仿真时长；按任务阶段分别统计 | 与任务时间窗或最长允许航时比较 |
| `MISSION_COMPLETION` | 已完成任务对象或订单数 / 任务对象或订单总数 | 由任务状态和实际到达记录计算 |
| `BUILDING_COLLISION` | 航迹体积与建筑白模、障碍物体积发生交叠的次数（运行规则来源为 `OBSTACLE` 或建筑关系冲突） | 大于 0 即为硬冲突；记录航空器、时刻和相交对象 |
| `GROUND_CLEARANCE` | 航迹到地形、建筑顶部和地面敏感区的最小垂直/水平净距 | 小于任务阈值即为地面风险；穿越或坠落为硬冲突 |
| `NO_FLY_INTRUSION` | 航段进入限制飞行区的相交次数和位置（运行规则来源为 `NO_FLY_ZONE` 或 `RESTRICTED_AIRSPACE_CROSSING`） | 大于 0 时方案不可执行 |
| `AIR_CONFLICT` | 两架航空器在同一仿真时段内的三维距离低于机间隔离阈值（运行规则来源为 `SEPARATION`） | 记录冲突对、最近距离、持续时间和位置；硬冲突不得执行 |
| `PERFORMANCE_LIMIT` | 速度、高度、爬升率、载荷、航程等是否超出机型参数 | 任一航段超限即为硬冲突；不得用插值跳过航段 |
| `ENERGY_CONSUMPTION` | 按航段距离、速度、高度变化、载荷、风场和机型功率模型积分的能量消耗 | 与可用能量及返航余量比较 |
| `ENERGY_RESERVE` | 关键时刻和降落时的剩余能量 / 额定可用能量 | 低于任务余量即为风险或硬冲突，按任务设置执行 |
| `CHARGE_SWAP_FEASIBILITY` | 充电或换电时间、站点容量、可用电池和任务时刻是否满足 | 时间或设备不足时方案不可执行 |
| `BATTERY_DEGRADATION` | 电池健康度、循环次数和温度对可用容量及功率的折减 | 折减后的容量用于能量计算，不能使用额定容量代替 |
| `ON_TIME_DELIVERY` | 实际到达时间不晚于订单最晚时间的订单数 / 已完成或延误订单数 | 由仿真到达时间计算，不能由调度表直接判定 |
| `TASK_COVERAGE` | 实际完成并满足采集条件的巡检对象数 / 对象总数 | 按对象完成状态和覆盖半径计算 |

`BUILDING_COLLISION`、`NO_FLY_INTRUSION`、`AIR_CONFLICT`、`PERFORMANCE_LIMIT` 和不可恢复的 `ENERGY_RESERVE` 属于硬约束；其他指标是否为硬约束由教师在任务模板中指定。指标缺少运行数据时显示“未生成”，不显示通过。

### 4.3 能量、充换电和损耗

能量计算按仿真步长推进。每个航段使用实际速度、爬升/下降功率、载荷、风场和电池健康度计算消耗；悬停、等待、起降和应急动作单独计入。充电按站点功率和可用时段计算，换电按换电工位、备用电池和换电时长计算。任务开始时的电量、换电次数、充电等待和电池损耗全部写入运行记录。

如果预计到达主降落点或备降点时低于返航余量，方案在预检阶段标记为不可执行；运行中因事件造成能量不足时，系统只允许任务配置中的返航、备降、任务转移或迫降动作。不能通过直接把航空器状态改为“已到达”绕过能量计算。

## 5 三类场景任务

### 5.1 城市编队表演

**教师设置**：表演区域、起降区、飞行区、观众区、地面隔离区、建筑和地形、编队规模（100/500/1000/3000 架）、固定程序、编队间距、最小空中隔离、最大高度、起飞间隔、返航条件和异常事件。5000 架仅保留为兼容运行聚合和后续目标环境扩展，不属于当前 V1.0 可创建的任务模板。

**学生方案**：规划起降批次和航线，分配编队，设置时间同步、间隔、返航和分区降落顺序。学生可提交不同的批次和航线组合。

**仿真判定**：计算每架飞行时间、程序完成、建筑/地面净距、编队间空中冲突、性能限制、事件处置时效和最终降落状态。程序完成但发生建筑碰撞或空中冲突时，方案仍判定不合格。

当前需求不包含舞步图案编辑或灯光编排。固定程序作为场景输入，学生提交的是可执行的飞行组织方案。

### 5.2 城市低空物流

**教师设置**：中心机场、配送点、主/备航线、建筑和限制区、订单数量（3/5/10/20/50）、时限、机队、载荷、充电站、换电站、备用电池和突发事件。

**学生方案**：编辑去程、返程和备降航线，分配订单和航空器，安排起飞时刻、等待、充电/换电和应急调整。配送节点、订单和航线必须在二维 GIS 中具有关联关系。

**仿真判定**：验证航线与建筑、限制区和机型能力；运行时计算实际航时、订单到达时间、建筑/地面风险、航空器间冲突、能量余量、充换电等待和动态重调度结果。订单完成率和准时到达率只使用仿真到达时间计算。

### 5.3 垂起广域巡检

**教师设置**：任务区域、地形和建筑、主/备降点、巡检对象、覆盖半径、机型阶段参数、规模（1/5/20 架）、通信覆盖、能量余量和任务转移条件。

**学生方案**：划分任务对象，设计垂直起飞、前转换、巡航、巡检、返航、后转换和垂直降落航段，安排备降点、能量补给和集群重组。

**仿真判定**：计算地形净空、建筑关系、阶段性能、对象覆盖、飞行时间、能量消耗、备降可达性、空中冲突和任务转移后的完成率。任一航空器未完成转换阶段或到达备降点时能量不足，相关方案不得判为可执行。

## 6 GIS、仿真与结果页面

二维 GIS 用于编辑和检查点、线、面、航线、建筑、障碍物、限制区、起降点、配送点、巡检点及充换电设施。三维场景显示建筑高度、地形、航迹和航空器状态。二、三维使用相同对象编号、WGS84 坐标和仿真时钟；修改航线后必须重新进行预检。

结果页面按方案显示：

- 方案状态：可执行、存在风险、不可执行或未运行；
- 任务完成率、实际飞行时间、准时率和任务覆盖率；
- 建筑碰撞次数、地面最小净距、空中冲突次数/最近距离/持续时间；
- 机型性能超限、单机能量曲线、返航余量、充电/换电等待和电池损耗；
- 事件处置时间、动作结果和未完成任务；
- 可定位到具体航空器、航段、仿真时刻和地图对象的运行记录。

VTL 方案检查直接读取区域包中的 BUILDINGS、RESTRICTIONS 特征：航段与建筑/障碍物水平相交且高度区间重叠时生成 `BUILDING_COLLISION` 或 `OBSTACLE_COLLISION`，穿越限制面时生成 `RESTRICTED_AIRSPACE_CROSSING`；多机检查按航段时间区间插值计算最近三维距离，不以航点间距代替运行检查。

结果比较以指标值和约束状态为依据。教师可以选择一套方案作为课堂讲评对象，但学生成绩不因采用不同的合格方案而被扣分。

## 7 教师与学生操作

### 7.1 教师

1. 选择场景模板和规模。
2. 配置地图资源、建筑、地形、机型、机队和保障设施。
3. 设置任务目标、事件、硬约束和指标阈值。
4. 预览任务，确认所有资源和指标都有计算来源。
5. 发布任务到班级或指定学生。
6. 查看学生方案、运行结果和指标明细；必要时要求学生重新提交方案。
7. 按指标结果和方案过程给出课程成绩，保留原始运行记录。

### 7.2 学生

1. 阅读任务目标、资源条件和机型参数。
2. 在二维地图中设计方案，完成空间、性能和能量预检。
3. 保存方案版本并提交运行。
4. 仿真运行中按允许动作处理事件。
5. 运行结束后查看指标、定位问题、复制方案并重新运行。
6. 提交达到任务条件的方案和说明。

首次进入时只提示当前操作所需的步骤；不显示与任务无关的说明文本。窄屏布局将地图属性和结果面板改为抽屉，主操作保持可见。

## 8 当前代码入口与验收

- GIS 与对象编辑：`apps/web/src/components/` 下 V3 地图和场景工作区；
- 航线、建筑和性能检查：`packages/simulation/src/logistics-route.ts`、`packages/simulation/src/vtl-runtime.ts` 及服务端场景服务；
- 运行和事件：`apps/server/src/v3/*runtime`；
- 评价指标：`apps/server/src/v3/*review`；
- 任务发布和资源绑定：`apps/server/src/v3/assignments`；
- 场景模板和教学数据：`apps/server/src/seed.service.ts`；内置三场景示例评价项使用 `SIMULATION_EVIDENCE`，只读取服务端仿真指标，不要求学生填写文字答案。

验收必须使用实际方案输入运行仿真，不能只检查页面是否显示文字。每个场景至少准备两套几何不同但均可执行的方案，以及一套必然触发建筑冲突、空中冲突或能量不足的方案，确认系统能区分合格与不合格结果。验收记录包括输入方案版本、资源版本、机型参数、仿真时钟、指标值和失败位置。

正式影像、DEM 和建筑资源须由目标环境资源包提供。仓库随附的广州北部教学建筑数据可用于功能联调；上海、贵州区域在正式资源包到位前只能使用场景清单中的教学回退数据。

## 10 方案题判定补充

题库中的规划题、时刻表题和场景决策题均对应一个可运行的学生方案。学生填写的文字仅用于说明调度理由、处置动作和方案假设，不作为合格判定依据。合格判定只读取方案版本和仿真运行记录。

仿真服务在统一仿真时钟下计算以下结果：

- **航时**：航空器从实际起飞到实际着陆的持续时间；
- **建筑碰撞**：三维航迹与建筑实体相交的次数、航空器编号和发生时刻；
- **限制区侵入**：航段进入限制飞行区的次数、对象和时刻；物流指标编码为 `NO_FLY_INTRUSION`，垂起资源检查使用 `RESTRICTED_AIRSPACE_CROSSING`；
- **地面净距**：航迹到地面、建筑顶部和地面敏感区的最小距离；
- **空中冲突**：同一时刻两架航空器的三维距离、持续时间和最近位置；
- **性能限制**：速度、高度、爬升率、载荷、航程和模式转换是否超出机型参数；
- **能量与保障**：按飞行阶段、风场、载荷、悬停和电池健康度计算能量消耗，并检查充电功率、换电时长、工位和备用电池；
- **任务结果**：订单到达时刻、准时率、巡检覆盖率、表演程序完成度和事件处置时效。

每项结果包含指标编码、单位、实际值、阈值和状态（通过、风险、失败、未生成）。缺少航迹、建筑高度、机型参数或能源设施数据时，状态为“未生成”，不得按通过处理。教师可以设置硬约束，也可以将指标作为讲评项；系统不从多套合格方案中选择唯一答案。
