# 高巨低空集群虚拟仿真实训平台系统设计与实施方案

## 1 概述

### 1.1 任务来源

本方案依据项目源码、需求设计、技术架构设计、开发进度计划和会议整改记录整理，用于代码交接、部署配置、教学试用和阶段验收。平台面向大专院校低空无人机相关专业的教师、学生和平台管理员，重点解决实训任务发布、地图规划、仿真运行、结果评价和过程留痕之间断开的实际问题。

### 1.2 功能用途

教师创建课程、班级和实训任务，选择城市集群表演、城市物流配送或垂起广域巡检场景，使用分步向导配置区域、对象、航线、规则和事件，预检后发布版本。学生从任务列表进入规划工作区，在二维地图完成点位、区域和航线编辑，切换三维查看高度、建筑和运行态势，保存方案并提交仿真。平台保存版本、运行快照、事件和评价证据，教师可按学生、任务和状态查看进度并导出结果。

### 1.3 研制依据

本方案使用仓库内的需求设计、技术架构设计、开发计划、地图迁移方案、场景操作手册和会议整改材料作为项目依据。仓库未提供需要强制引用的合同编号或外部标准编号，因此不新增未经核实的条款和结论。

### 1.4 引用文件

实际素材保存在 `docs/素材库/`。其中需求与架构文本描述角色、场景、页面字段、事件、规模验收和技术约束；源码是接口、数据结构和运行行为的直接依据。

### 1.5 术语与缩略语

| 术语 | 含义 |
| --- | --- |
| 2D GIS | 基于经纬度的平面规划地图，承担点位、区域和航线编辑 |
| 3D | Cesium 三维视图，用于地形、建筑高度、飞行高度和运行态势观察 |
| 方案版本 | 学生或教师一次可恢复的规划数据快照 |
| 预检 | 发布或提交前的规则、资源和字段完整性校验 |

## 2 功能以及技术指标

### 2.1 总体要求

平台以任务为入口，以地图为主要操作面。教师和学生先看到当前任务、状态和下一步操作；说明文字只解释决策所需信息。二维地图是规划数据的主编辑面，三维与二维使用同一组对象 ID、坐标和航线数据。

### 2.2 软件要求

当前可运行实现为 Vue 3、TypeScript、Vite、Element Plus、Cesium 1.143；服务端为 NestJS、TypeORM、PostgreSQL/PostGIS；服务端采用 NestJS 模块化单体，异步报告、资源处理等作业由独立 Worker 进程执行；场景运行服务以会话 checkpoint 推进状态，不把 Worker Thread 写成当前运行内核。文件资产支持本地目录和 MinIO；文档服务支持 OnlyOffice；Nginx 用于生产 HTTPS 网关。需求材料中出现的 Java、MySQL、Redis、WebSocket 不属于当前实现，部署时不得将其写成已接入组件。实时更新当前使用 SSE，并保留 HTTP 查询回退。

### 2.3 硬件和网络

开发环境使用 Node.js 24 和 Docker Compose。生产配置需要 PostgreSQL/PostGIS、对象存储和 HTTPS 网关；Cesium 资源通过受控的本地离线目录或部署方允许的资源地址提供。离线地图须将影像、建筑 GeoJSON、地形和可信资源包放入受控目录。正式服务器、终端数量、带宽和存储容量应根据学校机房实测结果确定，代码不虚构固定配置。

### 2.4 容量和验证口径

仓库已提供表演 3000 架、物流 50 架/100 单、垂起 20 架的验收脚本和夹具入口。它们是目标规模门槛，不能替代目标机房的长时实测；正式结论应使用同一目标标签、真实凭据、运行中的会话和现场签字证据。单元测试、类型检查和构建结果只证明代码层正确，不能证明目标机房的帧率或并发指标。

## 3 总体方案

### 3.1 设计原则

系统采用任务优先、渐进展开、数据可恢复和二维规划优先原则。地图操作需要提供当前工具、选中对象、坐标反馈、保存状态和错误恢复入口。影像、地形或建筑资源不可用时，在浏览器仍具备 WebGL 能力的前提下保留 Cesium 二维对象编辑，资源状态通过地图提示栏反馈。WebGL 不可用时，Cesium 的二维和三维场景均无法创建，页面只能保留表单、列表和已保存数据等非地图入口，不能表述为存在二维地图降级。

### 3.2 应用场景

教师在课程中发布任务，学生在课堂或课后完成规划和仿真，教师在进度、回放和评价页面复核证据。管理员负责用户、环境、资源包、备份和生产配置。三类场景共享用户、任务、地图资源、对象、航线、运行快照和评价模型，但保留各自的规则与事件字段。

### 3.3 总体设计

前端工作区把向导步骤、列表选择、地图事件和保存动作连接到同一份响应式计划。服务端通过 REST 控制资源、课程、任务、方案和运行；SSE 推送运行变化，HTTP 在连接不可用时补偿查询。PostgreSQL 保存业务和空间字段，运行服务读取冻结版本并把会话状态写入 PostgreSQL checkpoint；异步 Worker 进程负责报告、资源等后台作业。文件服务保存文档、地图和报告。

数据主链路为：`任务模板 → 发布版本 → 学生方案 → 预检 → 运行会话 → 快照/事件 → 评价证据 → 导出报告`。每一步携带项目或版本 ID，避免学生修改草稿影响已经发布的教学版本。

## 4 分模块技术方案

### 4.1 教学与任务

教师工作台提供课程、班级、模板、任务、事件和学生进度入口。创建任务使用分步向导：基础信息、场景数据、规则与事件、预检、发布。学生首页用全部、未开始、进行中、已提交、已完成筛选任务，保留搜索和下一步操作。

### 4.2 二维 GIS 规划

二维地图显示底图、区域边界、建筑、起降点、任务点、配送节点、限制区、障碍物和航线。地图点击先通过 globe.pick 获取地表坐标，资源未完成时回退到 pickEllipsoid；坐标转换后按区域约束校验。点位、折线和多边形编辑均返回统一的经纬度对象，保存动作写入方案草稿并生成版本事件。图层面板只改变可见性，不删除数据。

二维地图的交互闭环为：选择工具 → 点击或拖拽 → 读取坐标 → 检查区域和规则 → 更新对象 → 标记未保存 → 保存或撤销。选择列表对象会定位并高亮地图对象，地图点击对象会回写列表选中状态；没有有效资源时提示原因和恢复操作。

### 4.3 二维与三维联动

2D 和 3D 使用相同对象 ID、场景版本、经纬度、航线航点和图层代码。物流规划、区域规划等同一工作区在模式切换时复用当前 Cesium Viewer，并通过 morph 切换 SceneMode，不因切换主动销毁该 Viewer。模式切换前由 `captureV3Camera` 记录屏幕中心、二维视野宽度、三维地面距离、朝向和俯仰；morph 完成后由 `restoreV3Camera` 按目标模式恢复中心与显示尺度。该快照只在当前 Viewer 生命周期内用于模式切换，不写入服务端方案或跨页面持久化。对象 ID、选中对象和编辑数据由工作区状态继续提供，区域聚焦仍由用户主动操作触发。三维按相机高度降低建筑细节，二维将离线建筑高度设为零以避免把规划平面误显示为立体柱体。

三维资源加载失败或地形超时时，只要浏览器仍具备 WebGL，地图保留 Cesium 二维模式和对象编辑；运行回放可继续使用快照和列表数据。浏览器不支持 WebGL 时，Cesium 二维、三维均不可用，系统只保留非地图页面和已保存数据入口。该降级路径只影响资源显示，不改变方案数据。

### 4.4 仿真、回放和评价

服务端按仿真会话的 checkpoint、仿真时间和场景规则推进运行，读取发布版本和学生方案的冻结快照，生成航空器、订单、任务、事件和告警记录。当前实时通道为 SSE，断线后由客户端使用 HTTP 查询恢复当前会话和最新快照；这与需求材料中的 WebSocket 不是同一协议。回放以时间轴选择已保存记录，评价以规则结果和教师意见组成证据，报告由后台 Worker 异步生成。

### 4.5 文件和资源

资源包、地图、模板和报告使用受控对象键；本地存储按工作区相对路径解析，识别 Windows 盘符路径并防止路径越界。MinIO 密钥、JWT、数据库密码、OnlyOffice 密钥、演示账号密码均从环境变量读取，仓库不保存可用凭据。

## 5 关键技术以及解决处理途径

### 5.1 统一地图和数据流

问题是不同工作区重复创建地图会增加状态分散风险。当前由 `V3UnifiedMap` 作为入口，路由到场景渲染器；物流规划在同一工作区内使用单一 `logistics-route` Viewer。地图事件携带对象 ID 和经纬度，工作区更新计划后回传渲染器。模式切换由地图组件在 morph 前后执行相机过渡快照，恢复屏幕中心和显示尺度；该状态不作为服务端方案字段保存。验收时通过切换模式、选择点位、拖动航点、切换图层、保存草稿五步检查对象和方案状态一致性，并在目标浏览器记录恢复前后的中心和比例尺误差。

### 5.2 资源和降级

问题是影像、地形或建筑加载慢时用户误以为页面失效。加载跟踪器区分影像、地形、图层和错误状态；地图提示说明当前资源状态。二维和三维都由 Cesium 按当前配置的影像、地形及建筑资源呈现，不把未验证的在线底图写成正式离线资源。超时后保留已有对象并提供重试，不把失败资源写入方案。

### 5.3 教学版本和恢复

问题是发布中的数据被草稿覆盖。服务端以版本和运行快照隔离编辑与执行，前端显示未保存状态，保存失败保留草稿并提示重试。重新进入任务时按项目 ID 恢复最后草稿，提交后使用冻结版本生成运行和报告。

## 6 通用特性设计

可靠性通过数据库事务、后台 Worker 作业租约、重试、运行 checkpoint 和文件路径校验实现；这些机制不等同于已完成的高可用集群或故障自动切换。安全性通过来源校验、生产环境强制密钥、HTTPS、可信资源包和不提交凭据实现。维护性通过共享类型、场景流程配置、地图适配层和脚本化验收实现。测试性通过共享、仿真、服务端和前端单元测试以及类型检查和生产构建实现。适配性通过环境变量切换地图、存储、网关和报告服务实现。

## 7 管理措施

代码改动按功能域复核，地图、服务端安全和文档分别检查。提交前执行类型检查、构建、服务端测试、前端测试；目标机房再执行三场景长时验收。影像、地形或建筑资源故障且 WebGL 可用时，优先保持二维规划、任务保存和已发布版本；WebGL 不可用时，优先恢复表单、列表、任务保存和已发布版本，地图功能需等待具备 WebGL 的终端。

## 10 指标符合性

当前本地代码已通过仿真包 66 个测试、前端 101 个测试文件中的 404 个测试、服务端 99 个测试文件中的 434 个测试；服务端有 18 个跳过项，构建和类型检查通过。上述结果只对应当前执行环境。三场景规模、帧率、长时运行、20 人班级和正式 HTTPS 必须在目标环境按仓库脚本生成证据后判定，不以本地结果替代。

## 11 结论

当前实现已形成教师发布、学生规划、二维 GIS 编辑、二维/三维对象联动、仿真回放和三场景评价导出的代码链路；目标数据库、正式资源、浏览器长时运行和班级并发仍需按待办清单实测确认。界面以任务和操作为中心，删除重复标题并提升小字号可读性。后续工作以目标环境验收、地图资源正式授权、备份恢复见证和真实班级试用为主，清单见《实施待办清单》。
