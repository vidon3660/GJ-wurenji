## 场景实现

- `CITY_LOGISTICS`：订单、时间窗、航线、机池、运行事件和物流指标。
- `CITY_SHOW`：编队程序、批次起飞/降落、表演轨迹导入、机间间隔和程序检查。
- `VTOL_INSPECTION`：任务对象、航线阶段、垂起转换、地形剖面、备降和能源余度。

学生答案不是预设文本。教师发布任务后，学生提交方案并运行仿真；服务端根据建筑/障碍物、边界、禁限飞区、地形净空、机间冲突、飞行器限制、能源和事件结果计算指标。运行未完成或数据缺失时，不显示通过。通用仿真包含能源计算能力，但各 V3 工作台可编辑的能源字段由对应任务模板决定。

## 开发、测试和验收

根目录命令以 [`../README.md`](../README.md) 为准。常用入口：

```bash
npm ci
npm run setup
npm run typecheck
npm test
npm run build
npm run map:resources:acceptance
npm run test:delivery:qualification
npm run test:runtime-config
```

根目录运行、备份和浏览器验收命令自动加载 `.env`，显式环境变量优先。浏览器脚本使用 `playwright-core`，执行前准备应用、账号、场景夹具和 `CHROME_PATH`。`visual:smoke` 检查 V3 教师预设区域地图和学生任务列表，报告 `V3_REGION_MAP_2D_3D` 或无区域时的 `V3_REGION_CATALOG_EMPTY`；三场景 V3 运行区使用 `accessibility:v3-runtime:browser` 及对应的运行流脚本。旧 `accessibility:browser` 保留用于历史 V2 界面，不作为当前 V3 验收入口。没有目标环境、正式地图、GPU WebGL 或真实并发记录时，不得把脚本默认值写成现场验收结果。

## 文档维护规则

1. 需求变更先更新需求说明、场景输入和指标字典，再修改任务模板、代码和验收脚本。
2. 每个场景文档必须写清教师配置项、学生可编辑字段、输入资源、服务端计算方式和合格条件；应急内容注明所属场景和事件阶段。
3. 结果页只能显示服务端运行数据；没有完成运行时显示待计算或不合格。
4. 区域资源、机型参数或指标定义变化时新增版本，不覆盖已发布任务的快照。
5. 目标环境运行记录放入 `artifacts/acceptance/`；文档只描述命令、字段和判定规则，不把历史数字当作本次验收结果。
6. 文档中的启动命令、环境变量、端口和链接必须与 Compose、npm scripts 和代码同步；删除文件或脚本后同步移除入口链接。
