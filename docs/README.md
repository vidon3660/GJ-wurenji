## 文档维护规则

1. 新需求先更新 V3 需求或 R7 追踪矩阵，再更新实现文档；不新增带日期的重复任务书。
2. 架构变更只更新 V3.1 设计说明和 `系统设计与实施方案.md`；旧版本不再继续扩写。
3. 功能交付、回归命令和已知目标环境缺口写入 `开发交付记录.md` 或 `本轮改进与验收说明.md`。
4. 现场验收证据放入 `artifacts/acceptance/`，文档只链接证据类型和命令，不把本机结果写成正式环境结论。
5. 需求原文、架构基线和审计矩阵保留在仓库根目录，避免复制到 `docs/` 形成第二套版本。
