# 城市物流无人机离线地图改造总体技术架构

## 1. 范围

本文聚焦城市低空物流的离线影像和建筑白模资源。垂直起降巡检、无人机编队表演使用同一套区域资源包接口和二维/三维地图基础能力，场景规则分别由对应资源包提供。

## 2. 总体架构

```text
教师任务配置
  -> 物流区域资源包（WGS84、机场、配送点、候选等待/备降区域、规则）
  -> 学生区域分析与配送点确认
  -> Cesium 2D/3D 航线规划
       - 离线底图（教学区 JPEG 单幅影像）
       - 离线建筑白模（gd-north-core-buildings.geojson）
       - 地形/高程资源（有正式量测资源时挂载 quantized-mesh；否则明确回退）
       - Entity 航点、走廊、航段高度和编辑交互
  -> 静态规则检查
  -> 完整往返仿真验证
  -> 航线版本锁定与提交
  -> 订单调度、运行监控、事件处置、运行评估
```

## 3. 空间数据

- 业务坐标统一使用 WGS84 经度/纬度；高度字段明确为相对地面高度。
- 正式影像可以由 L17 GeoTIFF 转换为 JPEG/PNG 单幅离线影像，浏览器不直接读取 TIFF，转换后使用 `SingleTileImageryProvider` 按 `Rectangle` 叠加。
- 仓库演示资源为 `gd-north-core-buildings.geojson` 建筑轮廓数据。若 `height` 缺失，前端按稳定哈希生成 8 至 42m 白模高度，不能使用每次随机变化的高度，确保仿真可检查。
- 白模使用 Cesium `Entity.polygon`，`heightReference=RELATIVE_TO_GROUND`，`extrudedHeight=heightMeters`，材质为低透明度白灰色；航线规划仍以 Entity 取点和拖拽为主。
- 没有正式 DEM 时系统必须显示资源状态，不能把影像误标为高程。正式高程应发布为 Cesium quantized-mesh 或区域资源包声明的高程快照。
- 仓库默认附带一套可复现的轻量教学区离线演示资源（JPEG 单幅影像和 GeoJSON 建筑白模），用于保证 2D/3D 页面开箱可运行；执行 `npm run map:demo-assets` 可重新生成。该资源不是正式测绘成果，接入正式 L17/DEM 前必须替换资源包并同步更新 SHA-256。

## 4. 前端模块

- `V3LogisticsRouteMap`：离线影像、建筑白模、区域专题图层、节点、航线与航点编辑。
- `V3LogisticsRouteWorkspace`：配送点确认、航线增删改、版本、检查、仿真验证和提交。
- 航点编辑采用 Cesium `pickPosition/globe.pick` 获取 WGS84 坐标，再更新本地草稿；端点航点锚定机场和配送点，中间航点允许新增、拖动和删除。
- 运行期不开放新增航线；只能使用已检查/验证的方案。

## 5. 服务与资源发布

- 仓库演示资源路径为 `/map/logistics/gd-north-core-orthophoto.jpg` 和 `/map/logistics/gd-north-core-buildings.geojson`；正式环境通过区域资源包引用影像、建筑和高程版本。
- 生产部署优先使用签名区域资源包，开发环境允许通过 `VITE_LOGISTICS_OFFLINE_IMAGERY_URL`、`VITE_LOGISTICS_BUILDINGS_URL` 指向本地资源。
- 资源版本、覆盖范围、坐标系和 SHA-256 写入区域包，作为提交和评价快照的一部分。

## 6. 验收口径

1. 断网后物流规划页面仍能显示仓库内置的教学区离线影像和建筑白模。
2. 建筑白模全部有稳定正高度；轮廓与 GeoJSON 一致。
3. 学生可在地图取点新增中间航点、拖动航点、设置高度并保存。
4. 航线端点不能脱离机场/正式配送点；等待点和备降点只能从候选资源中选择。
5. 静态检查、完整往返验证和航线版本提交保持现有业务流程。
