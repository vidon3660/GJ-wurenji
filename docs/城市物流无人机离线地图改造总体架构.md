# 城市物流无人机离线地图总体技术架构

## 1. 范围与数据状态

物流、垂起巡检和编队表演共用区域资源包接口与二维/三维地图基础组件，各自使用不同的任务规则。地图数据分为三种状态：仓库内置教学资源、网络下载的待处理来源数据、经过区域导入和资源检查的课程资源。下载文件不会自动成为课程资源，也不会改写已经发布任务的地图版本。

仓库内置 `gd-north-core-orthophoto.jpg` 和 `gd-north-core-buildings.geojson`，用于教学区展示与界面开发。`npm run map:demo-assets` 可以重新生成这套演示文件；它们不是正式测绘成果。

## 2. 二维规划与三维运行

```text
教师配置任务和区域资源版本
  -> 学生确认物流节点、任务范围与运行条件
  -> Cesium 二维/三维航线规划
       - 影像或专题底图
       - 带来源说明的建筑轮廓与高度
       - quantized-mesh 地形显示与服务端高程采样
       - 航点、走廊、任务边界与禁限飞区
  -> 服务端空间和机型约束检查
  -> 往返仿真验证、航线版本提交
  -> 订单调度、运行监控、事件处置与结果分析
```

业务平面坐标使用 WGS84 经度/纬度。高度必须同时说明单位和参考面：建筑高度通常为相对地面的高度，DEM 高程可能采用正常高或正高，Cesium 笛卡尔坐标需要一致的椭球高解释。不能直接混用建筑高、相对起飞点高度和 DEM 高程；资源发布前应完成必要转换。

前端 `V3LogisticsRouteMap` 显示影像、建筑、区域图层、节点和航线，`V3LogisticsRouteWorkspace` 管理航线编辑、检查、验证与版本提交。新增、拖动航点会更新同一份方案草稿；运行阶段使用已检查的航线版本。

## 3. 可获取的数据来源

| 来源 | 可获得内容 | 使用限制 |
| --- | --- | --- |
| [OpenStreetMap](https://www.openstreetmap.org/copyright)，通过 [Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API) 查询 | 建筑轮廓、部分高度和层数属性 | 地区覆盖和属性完整性不同；下载脚本只处理闭合建筑 way，不保证覆盖全部多面关系建筑。保留贡献者署名和 ODbL 许可说明 |
| [AWS Terrain Tiles](https://registry.opendata.aws/terrain-tiles/) / [Mapzen 数据说明](https://github.com/tilezen/joerd) | Skadi HGT 高程；来源还提供 Terrarium 和 GeoTIFF 地形瓦片 | 这些是高程数据，不是遥感影像，也不是 Cesium quantized-mesh。来源包含多种地形产品，需核对分辨率、空值和垂直基准 |
| [Copernicus DEM](https://registry.opendata.aws/copernicus-dem/) GLO-30 | COG GeoTIFF，可按区域裁剪 | GLO-30 为地表模型，可能含建筑与植被表面；不能直接当成裸地高程叠加同一建筑高度。需保留产品说明并处理垂直基准 |
| Cesium ion 世界地形、世界影像、OSM Buildings | 在线三维显示资源 | 需要有效 token 和相应访问权限；显示层不自动转为服务端碰撞几何 |

公共 OpenStreetMap 栅格瓦片服务遵循[瓦片使用政策](https://operations.osmfoundation.org/policies/tiles/)，不能批量下载用于离线地图。离线影像应使用明确允许下载和分发的数据源、自有影像或学校提供的数据。HGT、Terrarium 和 GeoTIFF 地形瓦片不能作为影像替代品。

## 4. 下载小范围建筑和高程来源

在仓库根目录执行：

```bash
npm run map:fetch-assets
```

脚本入口为 [`scripts/fetch-map-region-assets.mjs`](../scripts/fetch-map-region-assets.mjs)，默认区域代号 `gd-north-core`，WGS84 范围为 `[113.287, 23.067, 113.323, 23.103]`，数组顺序为西、南、东、北。脚本从 Overpass 请求建筑，从 AWS Skadi 请求覆盖区域的 HGT，并生成高程采样 JSON 和来源清单。

可以通过环境变量改变下载范围和输出位置：

```bash
MAP_NETWORK_REGION=course-area-01 \
MAP_NETWORK_EXTENT=113.287,23.067,113.323,23.103 \
MAP_NETWORK_SAMPLE_GRID=37 \
MAP_NETWORK_OUTPUT_DIR=data/map/network-sources \
npm run map:fetch-assets
```

| 变量 | 用途 |
| --- | --- |
| `MAP_NETWORK_REGION` | 输出文件的区域标识 |
| `MAP_NETWORK_EXTENT` | `west,south,east,north` 四个经纬度数值 |
| `MAP_NETWORK_SAMPLE_GRID` | 每个方向的采样点数，默认 37；增加采样密度不会提高原始 DEM 精度 |
| `MAP_NETWORK_OUTPUT_DIR` | 下载结果目录，默认 `data/map/network-sources`，该目录不纳入 Git |

当前脚本用于小范围来源准备，只支持落在同一个 1° HGT 单元内的区域，不负责跨单元拼接、全市批量下载、地形瓦片金字塔或影像抓取。Overpass 端点不可用、没有建筑或有效高程不足时应重新选择来源或范围，不能以空文件补齐任务资源。

下载结果包含建筑 GeoJSON、高程采样 JSON、原始 HGT 及来源清单。区域文件名使用 `${MAP_NETWORK_REGION}` 前缀，例如 `gd-north-core-buildings-osm.geojson`、`gd-north-core-elevation-samples.json`、`gd-north-core-network-source.json`。来源清单记录范围、来源地址、获取时间、许可信息和文件 SHA-256；该清单不是已发布区域包。

脚本的解析和范围检查使用以下命令验证。测试结果应以本次命令输出为准，不能据此推定外部服务始终在线：

```bash
npm run test:map:fetch-assets
```

## 5. 建筑高度与地形处理

OSM 的 `height`、`building:levels` 和几何覆盖都可能缺失。层数乘以层高只能得到估算高度；前端缺少高度时使用的稳定哈希白模只服务于演示显示，不能作为测量高度或正式碰撞判定数据。没有可核实高度的建筑应在数据检查中列出，不能通过生成一个正数消除缺项。

正式建筑数据需要确定建筑轮廓、地面位置、建筑高度与来源精度，并写入服务器实际读取的区域资源。只在浏览器加载 OSM Buildings，并不能让服务端具备相应建筑的碰撞检查能力。

高程准备需要检查空值、采样间距、覆盖范围和垂直基准。HGT 高程采样 JSON供服务端读取和分析；Cesium 三维地形仍需要由适当的 DEM 转换为 quantized-mesh，或使用有权访问的在线地形服务。不能把 `.hgt`、原始 `.tif` 或 Terrarium PNG 地址直接填入 `VITE_DEM_TERRAIN_URL`。椭球地面回退仅用于显示，任务要求地形净空时不能把缺少高程解释为净空通过。

网络数据获取、DEM 裁剪和建筑下载完成之后，仍需按以下顺序准备课程资源：

1. 确定课程区域范围和任务所需的建筑、地形、影像、物流节点与禁限飞区。
2. 核对数据授权、坐标系、垂直基准和原始分辨率；补充建筑高度，清理空值和范围缺口。
3. 准备 quantized-mesh `layer.json` 及其瓦片，生成与之参考面一致的高程快照。
4. 编写区域导入配置，填写来源、范围、版本、资源路径和 SHA-256，执行导入与检查。
5. 创建并发布新资源包版本，由教师在新任务中选择该版本。已发布任务继续使用原有快照。

```bash
npm run map:region:import -- --config path/to/region-config.json --output-root data/map
npm run map:resources:acceptance
```

网络下载脚本不生成完整导入配置，以上 `path/to/region-config.json` 需要按区域导入格式准备；不能将 `*-network-source.json` 直接当作区域配置文件。

## 6. 资源服务与检查

演示资源路径为 `/map/logistics/gd-north-core-orthophoto.jpg` 和 `/map/logistics/gd-north-core-buildings.geojson`。生产区域资源位于 `MAP_DATA_DIR`；地图服务、资源检查和服务端地形采样使用一致路径。资源版本、覆盖范围、坐标系、文件哈希和高度定义必须写入课程资源包。

检查应分别覆盖显示和计算：

- 离线模式下，已绑定的影像和建筑文件可以加载；二维/三维切换保留任务对象和地图范围。
- 建筑轮廓与源 GeoJSON 一致；演示估算高度和经过核实的高度有明确区分。
- 学生可以新增、拖动中间航点并保存；端点保持机场和配送点约束。
- 净空检查使用有效高程，建筑碰撞检查使用服务器收到的建筑几何与高度；缺项不能判为通过。
- 航线检查、完整往返运行与版本提交使用同一任务资源版本。

网络来源可访问、高程文件下载成功和三维地图能显示，分别对应不同处理环节。只有区域数据完整、参考面一致并完成资源检查后，才能作为后续课程任务的地图输入。
