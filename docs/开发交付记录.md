## 2. 代码交付分区

### 2.1 V2 入口清理与公共教学能力

公共认证、课程、班级、学生、题库和首次引导仍由 `apps/server/src/education` 与 `apps/web/src/components/PlatformView.vue` 提供。旧版工作台入口按引用清理，不按目录名称整体删除；已经迁移到 V3 的任务、项目、运行和运行评估入口统一从 V3 工作区进入。

判定规则：

1. 已执行数据库迁移保留，不能通过删除旧迁移文件“清理”历史；
2. 认证、班级、课程、学生和题库属于公共能力，不能作为 V2 入口删除；
3. V3 项目只能调用 V3 API，历史 V2 数据保持只读兼容；
4. 删除服务端旧模块前先执行全仓引用搜索、类型检查和受影响测试。

### 2.2 三场景实时运行底座

三类场景统一使用运行会话、事件、告警、学生动作、快照和运行记录对象，领域服务分别位于：

- `apps/server/src/v3/logistics-runtime/`；
- `apps/server/src/v3/show-runtime/`；
- `apps/server/src/v3/vtl-runtime/`。

公共运行契约位于 `apps/server/src/v3/runtime/`，包括时钟、修订号、动作幂等、错误码、事件调度、SSE 续传、HTTP 查询恢复和教学夹具。运行会话从任务发布版本读取冻结的地图、场景和方案版本，运行中的事实写入 checkpoint、事件和动作记录，运行评估页面读取同一组运行记录。

当前服务端时钟由请求访问时按会话事实推进，不能在文档中写成已经部署独立后台 Tick。若以后改为常驻调度，需要单独设计多实例锁、重启恢复和作业租约。

最小确定性教学数据位于 `apps/server/src/v3/runtime/runtime-teaching-fixtures.ts`，用于单元、契约和并发隔离测试，不代表正式地图或生产数据。

### 2.3 地图资源和二维 GIS

地图资源治理由 `apps/server/src/v3/resources/` 和 `apps/web/src/map-resources*.ts` 负责；场景覆盖层支持草稿、版本、发布、归档、revision 并发校验和 GeoJSON 几何校验。正式区域资源必须提供影像、DEM、建筑、范围和校验摘要，仓库内 `apps/web/public/map/logistics/` 的影像与建筑文件是轻量教学演示资源。

二维规划的正式入口为 Cesium `SCENE2D`。教师覆盖层编辑器、物流学生规划和区域分析共享 WGS84 坐标、对象 ID、图层代码和选择事件。三维使用同一份对象数据，以 `SCENE3D` 查看地形、建筑高度和运行态势；切换模式时复用当前 Viewer，并通过 `captureV3Camera` / `restoreV3Camera` 保留中心、显示尺度和朝向。地图资源超时只改变资源提示和可见图层，不修改已保存方案。

OpenLayers 适配层的历史交付说明已合并到本项目的 Cesium 统一地图方案中；当前代码入口、测试和构建结果优先于历史分支名称。

### 2.4 教师任务、学生阶段和运行评估

教师使用 `V3AssignmentWizard.vue` 配置场景、模式、区域、资源、事件、班级和发布窗口，服务端只允许绑定已发布且匹配场景的资源版本。学生首页按任务状态筛选，首次进入时按账号隔离引导进度；没有教师发布的学生项目时不弹出无目标引导。教师进度页、场景运行评估页和物流运行评估页显示冻结快照、资源版本、运行历史、动作记录和评价状态。

## 4. 回归入口

提交前按变更范围执行：

```bash
npm test
npm run typecheck
npm run build
npm run test:setup
npm run test:map:resources:acceptance
```

地图资源和导入相关改动追加：

```bash
npm run test:map:region:import
npm run test:map:resources:acceptance
```

浏览器引导、三场景页面、WebGL、2D/3D 切换和目标规模长时运行必须在具备 Docker、浏览器和目标地图资源的环境执行；本地单元测试、构建和类型检查不能代替这些现场运行记录。

## 5. 目标环境交付门槛

以下事项由学校目标环境完成并留存报告：

1. 配置生产 JWT、数据库、对象存储、OnlyOffice 和 HTTPS 网关密钥；
2. 导入授权影像、建筑、DEM、三维资源和场景覆盖层，检查 URL、范围、版本和 SHA-256；
3. 用教师账号发布三个场景的教学任务，用真实学生账号完成规划、运行、处置、提交和运行评估；
4. 执行表演 3000 架、物流 50 架/100 单、垂起巡检 20 架的目标规模脚本；
5. 见证数据库、文件和报告备份恢复，以及升级和回滚；
6. 将报告写入 `artifacts/acceptance/`，使用同一个 `ACCEPTANCE_TARGET_LABEL`，再运行 `npm run acceptance:evidence` 汇总。

正式资源、目标机房性能、班级并发和人工签字记录均以目标环境实测为准，不能由开发机历史报告替代。

- 二维与三维继续使用同一份 WGS84 对象数据和选择状态；本轮没有增加仅展示文字的页面入口。

## 7. 2026-10-04 场景方案、仿真指标与结果权限

- 教师任务模板用于配置场景目标、地图资源、机型参数、规模、事件、充换电设施和指标阈值；学生进入任务后自行设计航线、任务分配、时刻表、能源补给和应急动作，可保存多套方案分别运行。
- 方案预检和仿真均由服务端计算。结果页面显示飞行时间、任务完成率、建筑/地面净距、建筑碰撞、航空器间空中冲突、性能超限、能量余量、充换电等待、电池损耗和准时率等指标；没有运行数据时不显示通过。
- 结果发布权限仍按教师控制。考核项目未发布评价前，学生只能看到方案状态和允许公开的汇总结果；教师端可查看完整的航空器状态、航段、时刻和事件记录。训练项目可按课程设置公开详细指标。
- 表演运行工作区把检查点中的导入程序关键帧传到浏览器，实时补帧和历史回放按 ENU 关键帧插值；没有导入程序时保留确定性回退轨迹。物流返航、备降和应急降落继续使用服务端动态位置快照。
- 物流准时率使用“模拟实际到达时间不晚于订单最晚到达时间”，分母包含已完成与延误订单；缺失时间戳不计入准时分子。
