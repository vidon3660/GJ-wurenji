# 本轮改进与验收说明

## 1 改进范围

本轮围绕大专师生的实际操作路径，处理界面密度、场景方案设计、仿真计算、二维 GIS 和二维/三维联动、跨平台文件路径、运行结果一致性、提交控制和生产配置安全。

## 2 已完成改进

| 方向 | 实际改动 | 使用结果 |
| --- | --- | --- |
| 学生首页 | 增加任务状态筛选、搜索和紧凑任务卡 | 学生直接找到未完成任务和下一步操作 |
| 工作区 UI | 缩短导航、删除重复 kicker 和双标题；将 6–9px 文字统一提升至 11px | 页面层级更少，文字可读 |
| 场景向导 | 表演、物流、垂起分别提供基础、对象、规则、航线和发布步骤 | 每一步有真实字段和预检，不靠重复说明占位 |
| 二维 GIS | Cesium SceneMode 2D 下统一对象选择、点线面编辑、图层显隐、区域约束、坐标回退 | 二维成为规划主界面；影像、地形或建筑资源异常时，在 WebGL 可用前提下继续编辑 |

| 服务端稳定性 | 识别 Windows 盘符路径、防止路径越界；报告字体候选增加环境检测 | 代码已覆盖路径规范化和字体候选选择；跨操作系统路径与字体仍按目标环境验收 |
| 仿真空间检查 | 按每架航空器的连续航段和仿真时间计算机间水平/垂直间隔；表演导入轨迹使用水平 5 m、垂直 3 m 的间隔阈值；建筑/障碍物按连续航段检查；地形高程缺失时输出未生成/不可判定状态，不用零高程代替 | 运行结果包含冲突对象、最近距离、持续时间、位置和阈值；缺失地形不会产生地面净空通过结论 |
| 能量与保障 | 计算电池容量折减、航段/悬停消耗、返航余量、充电功率、换电时长、能源站位置和备用电池；能量不足时不得把航线标记为已完成 | 方案可通过换电或充电补足任务，能源站参数无效时预检失败 |
| 评价结果清理 | 新建运行会话时清空未发布评价中的旧 `objectiveMetrics`，已发布评价保留 | 新运行不会继续使用上一轮方案的指标；教师重新计算后才生成当前运行指标 |
| 提交控制 | 学生方案提交和飞行结束报备在请求进行期间锁定输入；服务端对已提交作答的重试按原提交返回，避免重复写入 | 快速连续点击只产生一次提交；网络重试不会生成重复作答或重复报备 |
| 源码清理 | 删除仓库异常空文件 `{console.error(e)`，并补充相关回归用例 | 源码目录不再包含该异常文件 |
| 安全配置 | 数据库、对象存储、JWT、OnlyOffice 和演示密码改为环境变量 | 仓库不保存可用凭据，生产启动会校验必要配置 |

- 开发态与编译态数据库迁移命令均通过，本地 PostGIS 上完成 34 个迁移；应用健康与就绪接口正常。

测试使用当前开发环境和本地字体。三场景正式规模、长时、20 人班级、HTTPS、备份恢复和回滚仍需在目标环境执行仓库脚本并保存运行记录，不能用本地单元测试代替。浏览器不支持 WebGL 时，Cesium 的二维和三维均不可用；资源缺失降级与 WebGL 能力不足必须分开记录。

## 4 二维 GIS 验收步骤

教师进入场景编辑，打开或创建区域，确认底图和资源状态；在二维模式依次新增点位、绘制区域、添加航点，拖动一个航点，切换限制区和建筑图层，保存草稿并刷新页面。刷新后对象数量、经纬度、名称、颜色和图层状态应一致。点击列表对象应定位并高亮地图对象，点击地图对象应更新列表选中状态。

在保持一个对象选中的情况下切换 3D，记录对象选中状态、编辑数据以及镜头中心、距离和比例尺；组件应在 morph 前捕获相机过渡快照，morph 完成后恢复目标模式下的中心与显示尺度，同一工作区的 Viewer 不应因切换被销毁，建筑高度按三维显示。切回 2D，建筑回到平面规划表达，选中对象和草稿不变。断开地形或建筑资源后，在 WebGL 可用时检查二维对象编辑、保存和用户主动定位；若禁用 WebGL，应记录地图不可用并验证列表、表单和已保存数据入口。

## 5 三场景教学验收

表演场景检查区域、表演点、编队航线、时间同步和安全规则。物流场景检查物流节点、配送点、订单、无人机池、等待点、备用点和航线。垂起场景检查任务对象、主备起降点、可飞区域、障碍物和航线。三类场景均执行预检、发布、学生进入、保存、提交、运行、回放和教师评价。

## 6 方案计算验收

每个场景准备两套几何不同但满足条件的学生方案，以及一套故意触发风险的方案。系统应按仿真结果区分方案状态，不依据文字说明判断通过。

- 表演：检查每架飞行时间、建筑碰撞、地面净距、编队空中间隔、性能限制和程序完成。
- 物流：检查航线与建筑/限制区关系、订单实际到达时间、充电/换电等待、能量余量、机间冲突和动态调度。
- 垂起：检查转换阶段、地形净空、巡检覆盖、备降可达性、任务转移、能量消耗和机间冲突。

运行结束后结果页应显示实际飞行时间、最近建筑/地面净距、冲突对和持续时间、能量曲线、充换电记录及未完成任务。指标没有运行数据时显示“未生成”。建筑碰撞、空中冲突、机型性能超限和能量不足按任务设置作为硬约束，不能通过学生输入结果绕过。

## 7 本轮新增功能验收

1. 使用两架以上航空器在相交航段和等待点运行，检查每一对航空器的连续时间区间、最小水平距离、最小垂直距离、冲突持续时间和定位时刻。
2. 移除航段地形高程后运行，结果应显示地形净空未生成或不可判定，不能按地面高度为零计算通过。
3. 分别使用无能源保障、充电和换电方案运行，检查电池折减、消耗、等待时长、站点位置和返航余量；电量耗尽的航空器不能标记为已着陆。
4. 在已有未发布评价指标的项目上重新创建运行会话，确认旧指标被清空；已发布评价不被覆盖。
5. 连续点击学生方案提交和飞行结束报备，确认页面锁定并只生成一次提交；模拟网络重试，确认服务端不重复写入。

## 8 安全和配置验收

复制 `.env.example` 后替换所有 `replace-before-use` 和 `replace-with-*` 值，再启动 Docker。生产环境要求至少 32 位 JWT、HTTPS 来源、关闭同步建表和演示数据、配置资源包受信公钥以及对象存储密钥。演示账号密码仅从 `DEMO_*_PASSWORD` 注入，不写入 README、脚本或测试报告。
