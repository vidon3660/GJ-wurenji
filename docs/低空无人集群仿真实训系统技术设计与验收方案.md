# 低空无人集群仿真实训系统技术设计与验收方案

## 1 概述

### 1.1 任务来源

本方案用于仓库当前低空无人集群虚拟仿真实训 MVP 的技术设计、部署交接和目标环境验收。方案依据根目录需求规格、V3.1 系统设计说明书、现有 `docs/` 文档以及 `apps/`、`packages/`、`scripts/` 中的实现整理。平台服务教师配置实训任务、学生完成空间规划与运行处置、教师复核成果的教学环节。

### 1.2 功能用途

教师创建城市集群表演、城市物流配送和垂起广域巡检任务，配置区域、对象、航线、规则、事件并发布版本；学生在响应式工作台中完成二维地图规划，切换三维观察建筑和高度，提交运行并处置事件；系统保存草稿、发布快照、运行会话、告警、动作、评价和导出文件，支持回放与复盘。平台输出属于教学仿真材料，不作为真实飞行、行政审批、航线划设或物流运营依据。

### 1.3 研制依据

研制依据为根目录 `需求说明书-提取.txt`（V1 三场景范围与测试交付条款）、《低空无人集群教学仿真软件需求规格说明书 V3》《低空无人集群教学仿真软件系统设计说明书 V3.1》、R7 交付实施细则、当前部署说明和源代码。`低空无人集群教学仿真软件-V3需求差异与开发清单.md` 的迭代表主要覆盖表演和物流，当前实现已增加垂起巡检模块；垂起的题库、指标和目标环境验收以本方案 5.6 及题库实施说明为准。仓库未提供应强制引用的合同文号或外部标准编号，方案不新增未核实编号。

### 1.4 引用文件

引用入口包括根目录需求、系统设计和需求追踪矩阵，`docs/系统设计与实施方案.md`、`docs/城市物流无人机离线地图改造总体架构.md`、`docs/本轮改进与验收说明.md`、`docs/低空无人集群教学仿真软件-完整操作手册.md`、`deploy/README.md` 以及 `docs/README.md`。技术实现以代码和测试脚本为准。

### 1.5 术语与缩略语

| 术语 | 含义 |
|---|---|
| 2D GIS | Cesium `SCENE2D` 平面规划视图，承担点、线、面和航线编辑 |
| 3D | Cesium `SCENE3D` 视图，承担地形、建筑高度和运行态势观察 |
| 发布快照 | 任务发布时冻结的规则、资源、场景和教学配置 |

## 2 功能以及技术指标

### 2.1 总体要求

系统采用任务优先和版本冻结方式组织教学流程。二维视图作为规划主编辑面；三维视图复用同一 Viewer、对象 ID、坐标、选中状态和草稿。任务、方案、运行、事件、动作与评价均带项目或版本标识，教师修订草稿不影响已发布任务。

### 2.2 软件要求

前端使用 Vue 3、TypeScript、Vite、Pinia、Element Plus 和 Cesium 1.143；服务端使用 Node.js、NestJS、TypeORM、PostgreSQL/PostGIS；仿真代码位于 `packages/simulation`，报告和资源作业由服务端独立 Worker 领取。文件存储支持本地目录和 MinIO 适配器，生产入口由 Nginx HTTPS 网关提供。运行实时通道为 SSE，并保留 HTTP 查询恢复路径。版本、正式操作系统、浏览器、数据库补丁和字体来源见附录 A 清单。

### 2.3 硬件和网络要求

开发环境采用 Docker Compose；生产环境至少需要 API、数据库、对象存储、HTTPS 网关和按需启用的 Worker。影像、建筑 GeoJSON 和地形资源部署在受控目录或学校允许的资源服务中。服务器核数、内存、磁盘、终端数量、网络带宽和备份介质容量不在代码中固定，须由目标机房勘测后确认。

### 2.4 其他指标及口径

功能模板支持表演 100/500/1000/3000/5000 架、物流 3/5/10/20/50 架和垂起 1/5/20 架；当前浏览器规模夹具使用表演 3000 架、物流 50 架/100 单、垂起 20 架。根需求要求的 5000 架表演属于功能模板和正式目标环境验收范围，仓库现有短时浏览器夹具不能替代 5000 架长时证据。帧率、首屏时间、会话并发、长时稳定性、恢复时长和可用性均由目标环境脚本生成证据后判定。正式证据使用统一 `ACCEPTANCE_TARGET_LABEL`，并由现场签字文件确认。

## 3 总体方案

### 3.1 总体设计原则

系统把教师发布、学生规划、服务端校验、运行处置和教师复盘串成可追溯链路。前端负责编辑和即时提示，服务端负责权限、事务、权威校验、运行和评分；Worker 负责报告、资源和运行分段作业。外部地图、文档和对象存储均通过适配器接入，资源失败时保留已保存数据和非地图入口。

### 3.2 应用场景

教师工作台使用任务向导完成场景、区域、对象、规则、事件、预检和发布；学生工作台按阶段完成规划、检查、运行、应急处置、提交和复盘；管理员维护账号、资源包、备份、密钥和升级。表演关注编组、航线、安全和整体应急；物流关注中心机场、配送点、主备航线、订单、调度和动态事件；垂起巡检关注任务点、起降点、可飞区域、地形、能量和任务转移。

### 3.3 总体设计

#### 3.3.1 系统总体架构

```text
浏览器(Vue/Element Plus/Cesium)
        │ REST + SSE
NestJS 模块化单体 ── PostgreSQL/PostGIS（业务、空间、会话、事件、审计）
        │ 事务外盒/作业租约
独立 Worker ── 仿真与规则包 ── 本地文件或 MinIO ── PDF/资源处理
        │
Nginx HTTPS 网关、学校局域网或受控离线资源服务
```

#### 3.3.2 系统组成

教育与身份模块管理课程、班级、账号和发布；区域与资源模块管理影像、建筑、地形、规则和签名；场景模块分别维护表演、物流和垂起模型；运行模块保存会话、检查点、快照、事件、告警和动作；评价与文件模块生成复核结果和报告；审计模块记录操作、备份和升级。

#### 3.3.3 系统工作流程

`任务模板 → 发布快照 → 学生项目 → 草稿保存 → 服务端预检 → 运行会话 → 快照/事件/动作 → 评价复核 → 报告导出`。运行会话以整数仿真时间、版本输入和有序快照推进；SSE 断开时按会话序号和 HTTP 查询补齐状态。

#### 3.3.4 数据库设计方案

PostgreSQL 保存用户、课程、任务、项目、阶段、资源引用和审计；PostGIS 保存区域和空间对象；运行表保存会话状态、修订号、检查点和事件序列；物流域保存节点、航线、订单、调度与动态重调度；表演域保存编组、节目、阶段和动作；垂起域保存巡检任务、航线和任务转移。已发布对象使用不可变快照，文件表只保存对象键、哈希、版本和状态，不把凭据写入数据库。

## 4 分模块的技术方案

### 4.1 功能明细

| 模块 | 主要功能 | 主要使用者 |
|---|---|---|
| 教学与任务 | 课程、班级、向导、发布、阶段和进度 | 教师、管理员 |
| 响应式工作台 | 桌面双栏、窄屏抽屉、引导、保存和恢复 | 教师、学生 |
| 二维 GIS | 点线面、航线、区域约束、图层和对象选择 | 教师、学生 |
| 二三维联动 | SceneMode 切换、相机快照、建筑与地形观察 | 教师、学生 |
| 场景仿真 | 表演编队、物流调度、垂起巡检、事件处置 | 学生、教师 |
| 评价与交付 | 回放、评分、PDF、JSON/CSV 和打印 | 教师、管理员 |
| 资源与运维 | 地图资源、签名、备份、升级和回滚 | 管理员 |

### 4.2 响应式 UI 与教学工作台

工作台把当前任务、阶段导航、地图、属性面板、运行面板和告警入口放入同一壳层。样式表含 1320、1080、900、760、640、520 和 380 像素等响应式规则：宽屏展示左右面板，窄屏将面板折叠为抽屉并保留遮罩与返回入口；导航支持横向滚动，表格在面板内部滚动，地图容器设置可收缩宽度。物流地图根据容器宽度调整标签密度，避免窄屏遮挡航线。响应式验收只验证操作路径和可读性，具体设备清单见附录 A。

### 4.3 二维 GIS 规划

`V3LogisticsRouteMap`、区域地图组件和地图资源加载器创建 Cesium Viewer，加载影像、地形、建筑、区域、节点、限制区、障碍物和航线图层。点击通过 `globe.pick` 获取地表坐标，资源未就绪时回退 `pickEllipsoid`；坐标统一保存为 WGS84，经纬度先经过区域范围和规则检查再写入草稿。对象 ID 使用场景前缀，列表选择与地图点击互相回写；图层开关只控制可见性。航点新增、拖动、撤销、保存和重载形成可验收闭环。

### 4.4 二维与三维联动

同一工作区复用单一 Cesium Viewer，通过 `SceneMode.SCENE2D`、`SceneMode.SCENE3D` 和 morph 切换模式。切换前 `captureV3Camera` 保存屏幕中心、视野宽度、三维距离、朝向、俯仰和视口尺寸；morph 完成后 `restoreV3Camera` 按目标模式恢复中心与显示尺度。相机快照只用于当前 Viewer 生命周期的过渡，不写入服务端方案。建筑在三维按高度拉伸，二维按平面规划表达；地形或建筑加载失败时，在 WebGL 可用前提下保留二维编辑和保存。

### 4.5 建筑与地图数据

区域资源层使用 WGS84 与 EPSG:4326 GeoJSON；建筑实体读取 `height`、`heightMeters` 等字段，缺少正高度时按建筑 ID 的稳定哈希产生可复核教学白模高度。当前仓库实际随前端发布的离线建筑/影像只有广州北部教学区 `apps/web/public/map/logistics/`；上海外滩和贵州山区种子区域包含 manifest 建筑要素及预期 `/map/regions/{regionCode}/buildings.geojson` 地址，但对应正式文件尚未随仓库交付。加载失败时前端保留 manifest 建筑作为教学回退，并将资源状态标为待补齐，不把它当作正式测绘层。正式测绘影像、DEM、建筑版权、垂直基准和 SHA-256 由资源包清单声明；演示资源不作为正式测绘成果。

### 4.6 场景仿真与应急

表演仿真按阶段、编组、固定程序状态和安全规则推进，支持暂停后续起飞、暂停或中止表演、分组返航、分区降落和整体应急降落等白名单动作；不提供舞步导入、造型编辑或逐机轨迹编排。物流仿真读取中心机场、配送节点、主备航线、等待点、备降点、应急区域、订单批次和调度版本，执行航线静态检查、往返验证、订单状态和动态重调度。垂起巡检仿真读取任务点、起降点、可飞边界、障碍物和地形剖面，记录能量判断、任务转移和异常处置。事件、告警、学生动作和系统响应均写入运行证据。

### 4.7 文件、评价与审计

报告由 Worker 异步生成；文件资产保存对象键、版本、哈希、媒体类型和创建者。评价读取冻结运行证据和教师复核结果，生成 PDF、JSON 或 CSV；浏览器打印仅作为人工查看出口。审计记录发布、保存、运行控制、应急动作、资源激活、备份和回滚，凭据不进入报告。


### 4.8 教学任务、题库与师生闭环

教师通过五步向导创建任务草稿，依次配置场景与训练/考核模式、模板与区域、变量与事件、发布范围以及预览发布。内置场景在存在已发布兼容版本时默认带入题库；当前实现允许教师清空题库绑定，因此不绑定时只生成场景阶段成果，不生成题库作答入口。正式教学任务应绑定已发布题库版本，预览返回题库、学生数量和资源状态，预检将阻塞项与提醒项分开；发布后把场景资源、阶段策略、题库版本（如有）和目标学生冻结为任务快照。任务可发布到班级或指定学生，服务端为每名学生建立独立项目并保留任务版本。

题库版本状态为草稿、已发布和已归档。题目支持单选、多选、判断、规划、时刻表、场景决策和仿真证据七类题型。规划、时刻表和场景决策题用结构化必填字段自动给出基础判定；仿真证据题只读取服务端评价指标，指标缺失时保持待判定。学生接口不返回正确答案、解析和评分规则，教师复核接口返回答案与证据。学生可保存草稿，提交后进入只读；教师可重判仿真证据、逐题评分和填写评语，再发布评价。

三场景示例题库由 `apps/server/src/seed.service.ts` 提供：城市编队表演题库覆盖固定程序安全记录、编队安全、异常处置和 `EVENT_CONTROL` 示例阈值；城市低空物流题库覆盖限制区安全判断、航线规划、订单调度、航线中断应急和 `ON_TIME_DELIVERY` 示例阈值；垂起广域巡检题库覆盖任务点顺序、通信下降处置和 `TASK_COVERAGE` 示例阈值。表演题库仍保留历史标题“舞步训练”，但 `GJ-TRN-SHW-005` 不允许把题目字段解释成舞步导入或造型编辑。题库样例、教师操作、学生交互、响应式验收和待确认事项见《教学任务与三场景题库设计实施说明》。


## 5 关键技术以及解决处理途径

### 5.1 单 Viewer 的 2D/3D 状态连续性

目标是减少地图状态分散和模式切换后的对象漂移。单 Viewer 由 `createUnifiedCesiumViewer` 创建，切换时捕获并恢复相机快照，地图对象由同一组 ID 和数据源重绘。验证包含 2D 编辑、选择对象、切换 3D、检查中心与比例尺、切回 2D、保存并刷新；误差阈值由附录 A 的目标浏览器验收项确认。若 Viewer 被销毁或 WebGL 初始化失败，页面保留列表、表单和已保存数据入口。

### 5.2 空间数据与建筑白模

目标是让建筑关系可解释且可复现。加载器按资源包 URL 和区域范围选取 GeoJSON，实体使用稳定 ID 与高度字段；缺失高度使用确定性函数而非随机值。影像、地形、建筑分开报告加载状态，资源失败不写入错误数据。验收检查断网资源、建筑轮廓、稳定高度、坐标系、覆盖范围和哈希；正式 DEM 与版权未提供时按附录 A 阻塞发布。

### 5.3 运行一致性与恢复

运行会话在数据库保存状态、修订号、仿真时间、检查点和快照序列；运行服务在事务中锁定会话，动作携带幂等键，SSE 只推送已提交状态。事务外盒与作业租约使用数据库行锁和 `FOR UPDATE SKIP LOCKED`，Worker 心跳失效后允许重新领取。验证包含暂停/继续、重复动作、断线重连、服务重启、检查点恢复和报告重试；长时证据只接受目标环境报告。

### 5.4 资源包和部署适配

资源包导入时校验 JSON Schema、版本、SHA-256、签名公钥、覆盖范围和依赖，激活时锁定同类型版本并记录审计；已发布快照只引用已激活版本。地图、对象存储、文档和报告通过环境变量配置，开发本地目录与生产 MinIO 可替换。资源签名、公钥、密钥轮换和离线介质需按附录 A 确认。


### 5.5 题库判定与教学证据

目标是让教师题目、学生方案和仿真结果形成同一条证据链。题目编号、阶段编号和指标编码随题库版本冻结，学生答案通过项目修订号保存；运行服务产生的事件、告警、动作和客观指标写入项目时间轴，评价服务按任务快照读取这些证据。教师重判只重新计算服务端指标，不接受浏览器提交的伪造数值。

选择该方案是因为同一题库既需要即时反馈，也需要教师对规划和处置方案作专业判断。纯手工评分无法稳定提示未答和字段缺失，纯自动评分又无法替代教师对航线、编队和应急理由的判断，因此采用“字段完整性或精确答案自动判定 + 仿真指标阈值判定 + 教师复核”的组合。题库服务通过版本引用和不可变任务快照隔离历史任务，学生响应脱敏，教师响应才包含标准答案和评分规则。

验证覆盖题库内容校验、版本发布与归档、场景匹配、学生保存/提交、修订冲突、仿真证据重判、教师评分发布和学生只读回显。单元测试验证评分函数，服务端测试验证权限与快照，浏览器验收验证教师向导、学生题库抽屉、三场景路径和窄屏布局。题目分值、正式指标阈值、课程折算规则和正式题目清单以附录 A 的现场确认项为准；开发种子中的 90% 和 95% 仅作为示例题库规则。

### 5.6 三场景学生结果指标验算表

下表是当前评价服务写入 `objectiveMetrics` 的稳定编码。验收先检查代码、单位和证据来源，再检查题库阈值判定；数值阈值只允许绑定数值指标，状态字符串由教师结合方案和时间轴复核。`EVENT_CONTROL`、`ON_TIME_DELIVERY` 和 `TASK_COVERAGE` 的示例阈值分别为 90%、90% 和 95%，正式课程值必须由题库评审确认。

| 场景 | 指标编码 | 结果指标 | 单位/类型 | 当前实现的验算规则 | 题库使用 |
|---|---|---|---|---|---|
| 表演 | `PROCESS_COMPLETION` | 流程完成度 | % | 结束报备提交为 100，否则 0 | 可作阈值题 |
| 表演 | `RISK_IDENTIFICATION` | 风险识别率 | % | 已发现事件 / 已触发事件；无事件按 100% | 可作阈值题 |

| 表演 | `ACTION_DEADLINE` | 处置时限达标率 | % | 满足教师时限的动作比例 | 可作阈值题 |
| 表演 | `EVENT_CONTROL` | 事件控制率 | % | 已控制或结束事件 / 已触发事件 | 当前种子 `≥90` |
| 表演 | `EVENT_ESCALATION` | 事件升级数量 | 个 | 未及时控制并升级的事件数量 | 可作 `LTE` 阈值题 |
| 表演 | `ALERT_ACKNOWLEDGEMENT` | 告警确认率 | % | 已确认或解决告警 / 告警总数 | 可作阈值题 |

| 物流 | `RISK_IDENTIFICATION`、`AVG_RESPONSE_SECONDS`、`ACTION_DEADLINE`、`EVENT_CONTROL` | 发现率、处置时效、时限达标、控制率 | %/秒 | 从物流事件、动作和处置结果计算 | 可按指标配置题 |

| 垂起 | `TASK_COVERAGE` | 任务对象覆盖 | % | 完成任务对象 / 任务对象总数 | 当前种子 `≥95` |

## 6 通用特性设计

### 6.1 可靠性

采用数据库事务、不可变快照、会话检查点、作业租约、重试和死信状态，保存失败时保留本地草稿并提示冲突。数据库主从、高可用等级和故障切换时间不在当前代码中定义。

### 6.2 安全性

生产启动校验 JWT、数据库、对象存储和 ONLYOFFICE 密钥；Nginx 提供 HTTPS，Cookie 在生产启用安全属性；资源包使用受信公钥校验；文件路径做目录越界防护；普通用户按角色和项目授权。真实证书和密钥只放部署主机密钥管理位置。

### 6.3 维护性

共享类型位于 `packages/shared`，场景计算位于 `packages/simulation`，地图资源和相机逻辑位于前端适配层；数据库结构使用 migration，配置从 `.env` 注入。模块间通过应用服务、DTO 和领域事件交互。

### 6.4 测试性

仓库提供 simulation、server、web 的 Vitest 测试，地图编辑、资源就绪、响应式首页、运行流和目标环境脚本；类型检查和生产构建是交付前门禁。测试数量和通过状态须以本次目标环境运行报告为准。

### 6.5 保障性

部署提供健康检查 `/api/healthz` 与 `/api/readyz`、备份创建/验证/恢复、软件升级/回滚、Worker 健康检查和资源孤儿审计。运维人员保存命令输出、目标标签、时间和人工见证记录。

### 6.6 适配性

地图影像、地形、建筑和对象存储均可由配置或资源包替换；二维规划不依赖特定在线底图。业务坐标固定 WGS84，接入 GCJ-02 时仅在适配层转换。浏览器不支持 WebGL 时地图不可用，任务列表、表单和已保存结果仍可访问。

## 7 管理措施

### 7.1 项目团队管理

前端负责工作台、地图与浏览器验收；服务端负责模块、事务、权限和运行 API；仿真负责规则、场景计算和确定性；运维负责部署、资源、备份和回滚；验收人员负责现场环境、规模夹具、证据签字和问题闭环。每次发布关联源码版本、资源包版本、数据库 migration 和报告目录。

### 7.2 研制风险与措施

| 风险 | 影响 | 措施 | 责任 |
|---|---|---|---|
| 正式影像/DEM/建筑缺失 | 地图验收无法形成正式证据 | 先用演示资源完成流程，正式资源包通过签名和哈希门禁 | 运维、资源负责人 |
| WebGL 或浏览器能力不符 | 地图交互不可用 | 设备预检，保留表单和已保存结果入口 | 前端、验收 |
| 运行断线或 Worker 退出 | 状态丢失或重复执行 | 检查点、序列号、幂等键、租约恢复和重试 | 服务端、仿真 |
| 目标规模与本机不同 | 本地数字不能代表现场 | 使用目标标签、真实账号和长时脚本生成报告 | 验收负责人 |
| 密钥、证书或字体未获授权 | 生产门禁失败或报告不一致 | 现场准备并签字，禁止把凭据写入仓库 | 运维、管理员 |

## 11 结论
