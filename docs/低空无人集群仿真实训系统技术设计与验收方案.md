# 低空无人集群仿真实训系统技术设计与验收方案

## 1 概述

### 1.1 任务来源

本方案用于仓库当前低空无人集群虚拟仿真实训 MVP 的技术设计、部署交接和目标环境验收。方案依据根目录需求规格、V3.1 系统设计说明书、现有 `docs/` 文档以及 `apps/`、`packages/`、`scripts/` 中的实现整理。平台用于教师配置场景任务和验收条件，学生据此设计多套飞行方案并在 GIS 和仿真环境中运行，教师依据计算结果和方案过程给出课程评价。

### 1.2 功能用途

教师创建城市集群表演、城市物流配送和垂起广域巡检任务，配置区域、建筑、地形、机型、航线规则、能源设施、事件和指标阈值并发布版本；学生在二维 GIS 中设计航线、任务分配和保障计划，切换三维查看建筑高度和地形，启动仿真并处理事件。系统保存方案版本、仿真时钟、航空器状态、告警、动作、资源消耗和计算指标，支持多方案比较。平台输出属于教学仿真材料，不作为真实飞行、行政审批、航线划设或物流运营依据。

### 1.3 研制依据

研制依据为根目录 `需求说明书-提取.txt`（V1 三场景范围与测试交付条款）、《低空无人集群教学仿真软件需求规格说明书 V3》《低空无人集群教学仿真软件系统设计说明书 V3.1》、R7 交付实施细则、当前部署说明和源代码。`低空无人集群教学仿真软件-V3需求差异与开发清单.md` 的迭代表主要覆盖表演和物流，当前实现已增加垂起巡检模块；垂起的任务模板、指标和目标环境验收以本方案 5.6 及场景任务说明为准。仓库未提供应强制引用的合同文号或外部标准编号，方案不新增未核实编号。

### 1.4 引用文件

引用入口包括根目录需求、系统设计和需求追踪矩阵，`docs/系统设计与实施方案.md`、`docs/城市物流无人机离线地图改造总体架构.md`、`docs/本轮改进与验收说明.md`、`docs/低空无人集群教学仿真软件-完整操作手册.md`、`deploy/README.md` 以及 `docs/README.md`。技术实现以代码和测试脚本为准。

### 1.5 术语与缩略语

| 术语 | 含义 |
|---|---|
| 2D GIS | Cesium `SCENE2D` 平面规划视图，承担点、线、面和航线编辑 |

## 2 功能以及技术指标

### 2.1 总体要求

系统采用任务优先和版本冻结方式组织教学流程。二维视图作为规划主编辑面；三维视图复用同一 Viewer、对象 ID、坐标、选中状态和草稿。任务、方案、运行、事件、动作与评价均带项目或版本标识，教师修订草稿不影响已发布任务。

### 2.2 软件要求

前端使用 Vue 3、TypeScript、Vite、Pinia、Element Plus 和 Cesium 1.143；服务端使用 Node.js、NestJS、TypeORM、PostgreSQL/PostGIS；仿真代码位于 `packages/simulation`，报告和资源作业由服务端独立 Worker 领取。文件存储支持本地目录和 MinIO 适配器，生产入口由 Nginx HTTPS 网关提供。运行实时通道为 SSE，并保留 HTTP 查询恢复路径。版本、正式操作系统、浏览器、数据库补丁和字体来源见附录 A 清单。

### 2.3 硬件和网络要求

开发环境采用 Docker Compose；生产环境至少需要 API、数据库、对象存储、HTTPS 网关和按需启用的 Worker。影像、建筑 GeoJSON 和地形资源部署在受控目录或学校允许的资源服务中。服务器核数、内存、磁盘、终端数量、网络带宽和备份介质容量不在代码中固定，须由目标机房勘测后确认。

### 2.4 其他指标及口径

功能模板支持表演 100/500/1000/3000/5000 架、物流 3/5/10/20/50 架和垂起 1/5/20 架；当前浏览器规模夹具使用表演 3000 架、物流 50 架/100 单、垂起 20 架。根需求要求的 5000 架表演属于功能模板和正式目标环境验收范围，仓库现有短时浏览器夹具不能替代 5000 架长时运行记录。帧率、首屏时间、会话并发、长时稳定性、恢复时长和可用性均由目标环境脚本生成运行记录后判定。正式运行记录使用统一 `ACCEPTANCE_TARGET_LABEL`，并由现场签字文件确认。

## 3 总体方案

### 3.1 总体设计原则

系统把教师发布、学生规划、服务端校验、运行处置和课程评价按任务版本、方案版本和运行编号关联。前端负责编辑和即时提示，服务端负责权限、事务、系统规则校验、运行和评分；Worker 负责报告、资源和运行分段作业。外部地图、文档和对象存储均通过适配器接入，资源失败时保留已保存数据和非地图入口。

### 3.2 应用场景

教师工作台使用任务向导完成场景、区域、对象、规则、事件、预检和发布；学生工作台按阶段完成规划、检查、运行、应急处置、提交和运行评估；管理员维护账号、资源包、备份、密钥和升级。表演关注编组、航线、安全和整体应急；物流关注中心机场、配送点、主备航线、订单、调度和动态事件；垂起巡检关注任务点、起降点、可飞区域、地形、能量和任务转移。

### 3.3 总体设计

#### 3.3.1 系统总体架构

```text
浏览器(Vue/Element Plus/Cesium)
        │ REST + SSE
NestJS 模块化单体 ── PostgreSQL/PostGIS（业务、空间、会话、事件、操作记录）
        │ 事务外盒/作业租约
独立 Worker ── 仿真与规则包 ── 本地文件或 MinIO ── PDF/资源处理
        │
Nginx HTTPS 网关、学校局域网或受控离线资源服务
```

#### 3.3.2 系统组成

教育与身份模块管理课程、班级、账号和发布；区域与资源模块管理影像、建筑、地形、规则和签名；场景模块分别维护表演、物流和垂起模型；运行模块保存会话、检查点、快照、事件、告警和动作；评价与文件模块生成计算结果和报告；操作日志模块记录发布、运行控制、资源变更、备份和升级。

#### 3.3.3 系统工作流程

`任务模板 → 发布快照 → 学生项目 → 草稿保存 → 服务端预检 → 运行会话 → 快照/事件/动作 → 评价 → 报告导出`。运行会话以整数仿真时间、版本输入和有序快照推进；SSE 断开时按会话序号和 HTTP 查询补齐状态。

#### 3.3.4 数据库设计方案

PostgreSQL 保存用户、课程、任务、项目、阶段、资源引用和操作记录；PostGIS 保存区域和空间对象；运行表保存会话状态、修订号、检查点和事件序列；物流域保存节点、航线、订单、调度与动态重调度；表演域保存编组、节目、阶段和动作；垂起域保存巡检任务、航线和任务转移。已发布对象使用不可变快照，文件表只保存对象键、哈希、版本和状态，不把凭据写入数据库。

## 4 分模块的技术方案

### 4.1 功能明细

| 模块 | 主要功能 | 主要使用者 |
|---|---|---|
| 教学与任务 | 课程、班级、向导、发布、阶段和进度 | 教师、管理员 |
| 响应式工作台 | 桌面双栏、窄屏抽屉、引导、保存和恢复 | 教师、学生 |
| 二维 GIS | 点线面、航线、区域约束、图层和对象选择 | 教师、学生 |
| 二三维联动 | SceneMode 切换、相机快照、建筑与地形观察 | 教师、学生 |
| 场景仿真 | 表演编队、物流调度、垂起巡检、事件处置 | 学生、教师 |
| 评价与交付 | 回放、评分、PDF、JSON/CSV 和打印 | 教师、管理员 |
| 资源与运维 | 地图资源、签名、备份、升级和回滚 | 管理员 |

### 4.2 响应式 UI 与教学工作台

工作台把当前任务、阶段导航、地图、属性面板、运行面板和告警入口放入同一壳层。样式表含 1320、1080、900、760、640、520 和 380 像素等响应式规则：宽屏展示左右面板，窄屏将面板折叠为抽屉并保留遮罩与返回入口；导航支持横向滚动，表格在面板内部滚动，地图容器设置可收缩宽度。物流地图根据容器宽度调整标签密度，避免窄屏遮挡航线。响应式验收只验证操作路径和可读性，具体设备清单见附录 A。

### 4.3 二维 GIS 规划

`V3LogisticsRouteMap`、区域地图组件和地图资源加载器创建 Cesium Viewer，加载影像、地形、建筑、区域、节点、限制区、障碍物和航线图层。点击通过 `globe.pick` 获取地表坐标，资源未就绪时回退 `pickEllipsoid`；坐标统一保存为 WGS84，经纬度先经过区域范围和规则检查再写入草稿。对象 ID 使用场景前缀，列表选择与地图点击互相回写；图层开关只控制可见性。航点新增、拖动、撤销、保存和重载形成可验收流程。

### 4.4 二维与三维联动

同一工作区复用单一 Cesium Viewer，通过 `SceneMode.SCENE2D`、`SceneMode.SCENE3D` 和 morph 切换模式。切换前 `captureV3Camera` 保存屏幕中心、视野宽度、三维距离、朝向、俯仰和视口尺寸；morph 完成后 `restoreV3Camera` 按目标模式恢复中心与显示尺度。相机快照只用于当前 Viewer 生命周期的过渡，不写入服务端方案。建筑在三维按高度拉伸，二维按平面规划表达；地形或建筑加载失败时，在 WebGL 可用前提下保留二维编辑和保存。

### 4.5 建筑与地图数据

区域资源层使用 WGS84 与 EPSG:4326 GeoJSON；建筑实体读取 `height`、`heightMeters` 等字段，缺少正高度时按建筑 ID 的稳定哈希产生可计算的教学白模高度。当前仓库实际随前端发布的离线建筑/影像只有广州北部教学区 `apps/web/public/map/logistics/`；上海外滩和贵州山区种子区域包含 manifest 建筑要素及预期 `/map/regions/{regionCode}/buildings.geojson` 地址，但对应正式文件尚未随仓库交付。加载失败时前端保留 manifest 建筑作为教学回退，并将资源状态标为待补齐，不把它当作正式测绘层。正式测绘影像、DEM、建筑版权、垂直基准和 SHA-256 由资源包清单声明；演示资源不作为正式测绘成果。

### 4.6 场景仿真与应急

表演仿真按阶段、编组、固定程序状态和安全规则推进，支持暂停后续起飞、暂停或中止表演、分组返航、分区降落和整体应急降落等白名单动作；不提供舞步导入、造型编辑或逐机轨迹编排。物流仿真读取中心机场、配送节点、主备航线、等待点、备降点、应急区域、订单批次和调度版本，执行航线静态检查、往返验证、订单状态和动态重调度。垂起巡检仿真读取任务点、起降点、可飞边界、障碍物和地形剖面，记录能量判断、任务转移和异常处置。事件、告警、学生动作和系统响应均写入运行记录。

### 4.7 文件、评价与操作日志

报告由 Worker 异步生成；文件资产保存对象键、版本、哈希、媒体类型和创建者。评价读取冻结运行记录和教师评价结果，生成 PDF、JSON 或 CSV；浏览器打印仅作为人工查看出口。操作日志记录发布、保存、运行控制、应急动作、资源激活、备份和回滚，凭据不进入报告。


### 4.8 场景任务、方案与结果

教师在任务向导中选择场景、规模、区域和机型，配置建筑/地形/限制区、起降点、任务对象、充换电设施、事件、硬约束和指标阈值。发布后形成不可修改的任务版本。学生收到任务后自行设计航线、时刻表、航空器分配、能源补给和应急动作，可以保存多个方案版本并分别运行。

仿真服务端只接受方案几何、参数和动作，不接受学生手工填写的结果。运行过程中记录实际位置、速度、高度、能量、载荷、风场、事件和动作；评价模块据此计算飞行时间、建筑/地面风险、空中冲突、性能限制、能量余量、充换电等待、损耗、任务完成率和准时率。满足硬约束且达到指标阈值的方案均为合格方案，不设置唯一标准航线。

## 5 关键技术以及解决处理途径

### 5.1 单 Viewer 的 2D/3D 状态连续性

目标是减少地图状态分散和模式切换后的对象漂移。单 Viewer 由 `createUnifiedCesiumViewer` 创建，切换时捕获并恢复相机快照，地图对象由同一组 ID 和数据源重绘。验证包含 2D 编辑、选择对象、切换 3D、检查中心与比例尺、切回 2D、保存并刷新；误差阈值由附录 A 的目标浏览器验收项确认。若 Viewer 被销毁或 WebGL 初始化失败，页面保留列表、表单和已保存数据入口。

### 5.2 空间数据与建筑白模

目标是让建筑关系可解释且可复现。加载器按资源包 URL 和区域范围选取 GeoJSON，实体使用稳定 ID 与高度字段；缺失高度使用确定性函数而非随机值。影像、地形、建筑分开报告加载状态，资源失败不写入错误数据。验收检查断网资源、建筑轮廓、稳定高度、坐标系、覆盖范围和哈希；正式 DEM 与版权未提供时按附录 A 阻塞发布。

### 5.3 运行一致性与恢复

运行会话在数据库保存状态、修订号、仿真时间、检查点和快照序列；运行服务在事务中锁定会话，动作携带幂等键，SSE 只推送已提交状态。事务外盒与作业租约使用数据库行锁和 `FOR UPDATE SKIP LOCKED`，Worker 心跳失效后允许重新领取。验证包含暂停/继续、重复动作、断线重连、服务重启、检查点恢复和报告重试；长时运行记录只接受目标环境报告。

### 5.4 资源包和部署适配

资源包导入时校验 JSON Schema、版本、SHA-256、签名公钥、覆盖范围和依赖，激活时锁定同类型版本并记录操作记录；已发布快照只引用已激活版本。地图、对象存储、文档和报告通过环境变量配置，开发本地目录与生产 MinIO 可替换。资源签名、公钥、密钥轮换和离线介质需按附录 A 确认。


### 5.5 方案计算与多解判定

任务模板保存目标、空间条件、机型参数、能源设施、事件和指标定义。学生方案保存航点、航段高度和速度、航空器分配、起飞顺序、任务顺序、充电/换电计划、备降点以及事件处置动作。服务端预检先计算空间和性能硬约束，仿真结束后再计算时间、风险、能量和任务完成指标。

计算必须使用实际仿真状态：飞行时间取起飞到落地的仿真时间；建筑碰撞取航迹体积与建筑白模/障碍物体积的相交；地面风险取航迹到地形、建筑顶部和地面敏感区的最小净距；空中冲突取同一时段内两架航空器的三维距离、持续时间和最近位置；性能限制检查每个航段的速度、高度、爬升率、载荷和航程；能量按航段距离、速度、爬升、载荷、风场、悬停和电池健康度积分，并计入充电、换电和等待时间。

`BUILDING_COLLISION`、`NO_FLY_INTRUSION`、`AIR_CONFLICT`、`PERFORMANCE_LIMIT` 和低于返航余量的 `ENERGY_RESERVE` 默认是硬约束。教师可以在任务版本中调整阈值，但不能降低指标的计算来源。多方案比较显示指标向量和不满足项，不将某个方案标为唯一答案。

### 5.6 三场景结果指标

下列编码用于任务模板和评价接口。指标值只能由仿真服务端生成；没有运行数据时状态为“未生成”。

| 指标编码 | 计算内容 | 结果用途 |
|---|---|---|
| `FLIGHT_TIME` | 每架从起飞到降落的仿真时长 | 与任务时限、最长航时比较 |
| `MISSION_COMPLETION` | 完成订单/任务对象数 ÷ 总数 | 任务完成判定 |
| `BUILDING_COLLISION` | 航迹与建筑、障碍物体积的相交次数（运行规则来源为 `OBSTACLE` 或建筑关系冲突） | 大于 0 时方案不可执行 |
| `GROUND_CLEARANCE` | 航迹到地形、建筑顶部及地面敏感区的最小净距 | 与地面安全阈值比较 |
| `NO_FLY_INTRUSION` | 航段进入限制飞行区的相交次数和位置（运行规则来源为 `NO_FLY_ZONE` 或 `RESTRICTED_AIRSPACE_CROSSING`） | 大于 0 时方案不可执行 |
| `AIR_CONFLICT` | 航空器对的最小三维间隔、持续时间和次数（运行规则来源为 `SEPARATION`） | 与机间隔离阈值比较 |
| `PERFORMANCE_LIMIT` | 速度、高度、爬升率、载荷、航程超限次数 | 任一硬超限即失败 |
| `ENERGY_CONSUMPTION` | 分航段能量消耗，含起降、爬升、悬停、载荷、风场和损耗 | 与可用容量比较 |
| `ENERGY_RESERVE` | 关键时刻和降落时的剩余能量比例 | 与返航/备降余量比较 |
| `CHARGE_SWAP_FEASIBILITY` | 充电功率、换电时长、工位和备用电池是否满足时刻表 | 判断方案能否按时执行 |
| `BATTERY_DEGRADATION` | 健康度和循环次数造成的容量/功率折减 | 折减后容量参与计算 |
| `ON_TIME_DELIVERY` | 实际到达不晚于最晚时间的订单比例 | 物流任务指标 |
| `TASK_COVERAGE` | 满足采集条件的巡检对象比例 | 巡检任务指标 |

表演任务重点检查 `FLIGHT_TIME`、`BUILDING_COLLISION`、`NO_FLY_INTRUSION`、`GROUND_CLEARANCE`、`AIR_CONFLICT` 和程序完成；物流任务重点检查航线/建筑冲突、`ON_TIME_DELIVERY`、能量、充换电和订单完成；垂起任务重点检查转换阶段、地形净空、`TASK_COVERAGE`、能量、备降可达性和任务转移。

### 5.7 方案运行与成绩计算口径

场景任务不是文字问答模块。教师发布的是场景条件、机型参数、运行事件、指标阈值和评分量表；学生在二维 GIS 中编辑航线、航点高度、速度、任务分配、起飞时刻、充换电和应急动作，形成方案版本后提交仿真。文字字段只记录方案说明和处置理由，不参与方案是否可执行的计算。

服务端使用统一仿真时钟和版本化资源计算结果。建筑碰撞采用三维航段与建筑实体相交检测，地面风险采用航迹到地面/建筑顶部/敏感区的最小净距，空中风险采用同步轨迹的三维间隔和持续时间，性能限制读取机型速度、高度、爬升率、载荷、航程及模式转换参数，能源结果包含飞行消耗、电池健康度、充电功率、换电时长、工位容量和备用电池。物流额外计算实际到达时刻、准时率、订单完成率和动态调度结果；垂起额外计算转换阶段、巡检覆盖率、备降可达性和任务转移后的完成率。

每个指标保存 `code`、单位、实际值、阈值、状态和关联航空器/航段/仿真时刻。状态为“未生成”时不得显示通过；硬约束失败时方案标记为不可执行。多个方案均满足约束时均可作为合格方案，教师按指标结果和方案组织过程给出课程成绩，不比较文字答案是否与某个模板一致。

## 6 通用特性设计

### 6.1 可靠性

采用数据库事务、不可变快照、会话检查点、作业租约、重试和死信状态，保存失败时保留本地草稿并提示冲突。数据库主从、高可用等级和故障切换时间不在当前代码中定义。

### 6.2 安全性

生产启动校验 JWT、数据库、对象存储和 ONLYOFFICE 密钥；Nginx 提供 HTTPS，Cookie 在生产启用安全属性；资源包使用受信公钥校验；文件路径做目录越界防护；普通用户按角色和项目授权。真实证书和密钥只放部署主机密钥管理位置。

### 6.3 维护性

共享类型位于 `packages/shared`，场景计算位于 `packages/simulation`，地图资源和相机逻辑位于前端适配层；数据库结构使用 migration，配置从 `.env` 注入。模块间通过应用服务、DTO 和领域事件交互。

### 6.4 测试性

仓库提供 simulation、server、web 的 Vitest 测试，地图编辑、资源就绪、响应式首页、运行流和目标环境脚本；类型检查和生产构建是交付前门禁。测试数量和通过状态须以本次目标环境运行报告为准。

### 6.5 保障性

部署提供健康检查 `/api/healthz` 与 `/api/readyz`、备份创建/验证/恢复、软件升级/回滚、Worker 健康检查和资源孤儿操作记录。运维人员保存命令输出、目标标签、时间和人工见证记录。

### 6.6 适配性

地图影像、地形、建筑和对象存储均可由配置或资源包替换；二维规划不依赖特定在线底图。业务坐标固定 WGS84，接入 GCJ-02 时仅在适配层转换。浏览器不支持 WebGL 时地图不可用，任务列表、表单和已保存结果仍可访问。

## 7 管理措施

### 7.1 项目团队管理

前端负责工作台、地图与浏览器验收；服务端负责模块、事务、权限和运行 API；仿真负责规则、场景计算和确定性；运维负责部署、资源、备份和回滚；验收人员负责现场环境、规模夹具、运行记录签字和问题处理。每次发布关联源码版本、资源包版本、数据库 migration 和报告目录。

### 7.2 研制风险与措施

| 风险 | 影响 | 措施 | 责任 |
|---|---|---|---|
| 正式影像/DEM/建筑缺失 | 地图验收无法形成正式运行记录 | 先用演示资源完成流程，正式资源包通过签名和哈希门禁 | 运维、资源负责人 |
| WebGL 或浏览器能力不符 | 地图交互不可用 | 设备预检，保留表单和已保存结果入口 | 前端、验收 |
| 运行断线或 Worker 退出 | 状态丢失或重复执行 | 检查点、序列号、幂等键、租约恢复和重试 | 服务端、仿真 |
| 目标规模与本机不同 | 本地数字不能代表现场 | 使用目标标签、真实账号和长时脚本生成报告 | 验收负责人 |
| 密钥、证书或字体未获授权 | 生产门禁失败或报告不一致 | 现场准备并签字，禁止把凭据写入仓库 | 运维、管理员 |

## 11 结论
